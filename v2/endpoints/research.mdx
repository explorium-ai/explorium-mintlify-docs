</Info>

## Overview

Research runs a custom, AI-powered research task over a list of businesses or prospects. You supply either:

- a natural-language `query`, or
- a `prompt_template` plus a caller-defined `output_schema`

Results can optionally be grounded in real-time web data.

## Endpoints

| Entity | Sync | Async |
| :--- | :--- | :--- |
| Businesses | [`/v2/businesses/research/enrich`](/v2/research/businesses_research_enrich) | [`/v2/businesses/research/job`](/v2/research/businesses_research_job) |
| Prospects | [`/v2/prospects/research/enrich`](/v2/research/prospects_research_enrich) | [`/v2/prospects/research/job`](/v2/research/prospects_research_job) |

Both are `POST` and follow the standard [v2 conventions](/v2/conventions) — no `/bulk_enrich` suffix, and a single endpoint accepts one ID or a list of IDs.

<Note>
  During the beta, Research runs in **sync mode only**, even though the `.../job` variants are already present in the spec. The async variants follow the standard sync/async pairing via the [async job infrastructure](/v2/async-jobs).
</Note>

## Availability today

Research is already released as an early beta under v1, at:

- `POST /v1/businesses/research/bulk_enrich`
- `POST /v1/prospects/research/bulk_enrich`

In v2 these become the paths in the table above. The `/bulk_enrich` suffix is dropped, in line with the [no-bulk-endpoints convention](/v2/conventions#no-more-bulk-endpoints).

## Parameters

| Parameter | Description |
| :--- | :--- |
| `query` | Natural-language description of the research task |
| `prompt_template` | Template used instead of `query`, paired with `output_schema` |
| `output_schema` | Caller-defined schema describing the shape of the result |

<Warning>
  Full parameter reference, response format, and credit costs are not yet finalized and will be documented before GA.
</Warning>
