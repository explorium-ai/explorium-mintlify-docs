Every enrichment ships both a **sync** and an **async** variant, and every endpoint accepts either a single ID (a string) or a list of IDs. See [Conventions](/v2/conventions).

All paths below are `POST`.

| :--- | :--- | :--- |
| `contact_information` | `/v2/prospects/contact_information/enrich` | `/v2/prospects/contact_information/job` |
| `linkedin_posts` | `/v2/prospects/linkedin_posts/enrich` | `/v2/prospects/linkedin_posts/job` |
| `profiles` | `/v2/prospects/profiles/enrich` | `/v2/prospects/profiles/job` |

<Warning>
  **Renamed in v2.** The v1 `contacts_information` endpoint becomes `contact_information` (singular "contact"). Update both the path and any code that keys off the endpoint name.
</Warning>

## Response changes

These apply across enrichments in v2 — see [What's new](/v2/whats-new) for the full list:

- `entity_id` is no longer returned.
- `display_name` is removed from the business `linkedin_posts` response.
- The old nested `emails` and `phones` JSON fields are removed from the contact response.
- Address signals (`company_city`, `company_country_code`, `company_region`, `company_street`, `company_zip_code`) are removed from `company_ratings_by_employees`.
