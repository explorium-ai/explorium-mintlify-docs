Every enrichment ships both a **sync** (`.../enrich`) and an **async** (`.../job`) variant, and every endpoint accepts either a single ID or a list of IDs. See [v2 conventions](/v2/conventions) and [async jobs](/v2/async-jobs).

All enrichment endpoints are `POST`.

## Response changes

These apply across enrichments in v2 — see [What's new](/v2/whats-new) for the full list:

- `entity_id` is no longer returned.
- `display_name` is removed from the business `linkedin_posts` response.
- The old nested `emails` and `phones` JSON fields are removed from the contact response.
- Address signals (`company_city`, `company_country_code`, `company_region`, `company_street`, `company_zip_code`) are removed from `company_ratings_by_employees`.
