### Introduction

The **Contact details enrichments** API provides detailed information about individual prospects, including contact details, professional emails, and phone numbers. This API is crucial for lead enrichment, personalized outreach, and enhancing sales intelligence workflows.

<Icon icon="thumbtack" iconType="solid" color="red" /> **Key Benefits:**

- Access **validated contact information** for prospects.
- Get **SHA256-hashed email identifiers** (professional and personal) for ABM and ad-audience matching, without handling plain-text addresses.
- Ensure **accurate and up-to-date data** for prospecting and engagement.

### Endpoint: `POST /prospects/contact_information/enrich`

<Note>
  **v2:** this endpoint accepts either a single ID (a string) or a list of up to 50 IDs — the separate `/bulk_enrich` route is gone. See [v2 conventions](/v2/conventions).
</Note>

## Enrich by prospect details instead of IDs

`prospect_ids` is the primary way to call this endpoint. If you don't have Explorium IDs yet, you can send `prospects_to_match` instead: up to 50 people, described with the same fields the [Match prospects](/v2/prospects/match_prospects) endpoint accepts (`full_name`, `company_name`, `email`, `phone_number`, `linkedin`, `business_id`). Each person is matched and enriched in the same call. Send **either** `prospect_ids` **or** `prospects_to_match`, never both (that returns a `422`). Any `parameters` the endpoint takes work the same either way.

<CodeGroup>
```json Request body
{
  "prospects_to_match": [
    { "full_name": "Jane Doe", "company_name": "Acme Corp" },
    { "full_name": "John Smith", "company_name": "Unknown Co" }
  ]
}
```

```json Response (data shortened)
{
  "response_context": {
    "correlation_id": "9a1c0e7f4b2d4c6e8f0a1b2c3d4e5f60",
    "request_status": "success",
    "time_taken_in_seconds": 1.42
  },
  "data": [
    {
      "input": { "business_id": null, "full_name": "Jane Doe", "company_name": "Acme Corp", "email": null, "phone_number": null, "linkedin": null },
      "prospect_id": "4f1d9c2e7a3b5c8d0e6f1a2b3c4d5e6f7a8b9c0d",
      "data": { "...": "same fields as an ID-based request" },
      "warnings": []
    },
    {
      "input": { "business_id": null, "full_name": "John Smith", "company_name": "Unknown Co", "email": null, "phone_number": null, "linkedin": null },
      "prospect_id": null,
      "data": null,
      "warnings": []
    }
  ],
  "total_results": 1,
  "total_matches": 1
}
```
</CodeGroup>

Each row echoes its `input` and returns the matched `prospect_id`. People who don't match come back with `prospect_id: null` and `data: null`, and aren't charged. `total_matches` counts the matched rows.

<Note>
  **Need higher coverage?** The [asynchronous variant](/v2/prospects/enrichments/contact_information_job) supports **waterfall enrichment** — prospects that Explorium data cannot enrich are retried against a verified external provider. The `waterfall` parameter is available **only** on the async endpoint; passing it here returns a validation error.
</Note>

## Hashed identifiers for ABM

Add `hashed_identifiers` to `contact_types` to get each prospect's email addresses as **SHA256 hashes**, split into `hashed_professional_emails` and `hashed_personal_emails`. Hashed emails are the format ad platforms and ABM tools use to match audiences, so you can build and sync account-based audiences without handling plain-text addresses.

- **Cost:** 1 credit per prospect returned with hashed identifiers. Email (2 credits) and phone (5 credits) are charged as usual when requested in the same call.
- **Opt-in:** hashed identifiers are returned only when you request them. Omitting `parameters` returns email and phone, as before.
- **Gmail addresses** are hashed twice, as written and with the dots in the name removed (`jane.doe@gmail.com` → `janedoe@gmail.com`), so both variants are in the array.
- **No emails:** both arrays are `null` when the prospect has no email on record.

```json Response row with hashed identifiers
{
  "prospect_id": "4f1d9c2e7a3b5c8d0e6f1a2b3c4d5e6f7a8b9c0d",
  "data": {
    "hashed_professional_emails": ["9f2c3a51e0b44d7a8c6e1f3b2d5a7c9e0f1b3d5a7c9e1f3b5d7a9c1e3f5b7d9a"],
    "hashed_personal_emails": null
  }
}
```

## Body Params - Try Me Example

```
prospect_ids: ee936e451b50c70e068e1b54e106cb89173198c4
```

**Email Only (2 credits):**

```json
  {
    "prospect_ids": "ee936e451b50c70e068e1b54e106cb89173198c4",
    "parameters": {
      "contact_types": ["email"]
    }
  }
```

**Phone Only (5 credits):**

```json
{
    "prospect_ids": "ee936e451b50c70e068e1b54e106cb89173198c4",
    "parameters": {
      "contact_types": ["phone"]
    }
  }
```

**Both Email and Phone (5 credits) - Default behavior:**

```json
{
    "prospect_ids": "ee936e451b50c70e068e1b54e106cb89173198c4",
    "parameters": {
      "contact_types": ["email", "phone"]
    }
  }
```

**Hashed identifiers only (1 credit):**

```json
{
    "prospect_ids": "ee936e451b50c70e068e1b54e106cb89173198c4",
    "parameters": {
      "contact_types": ["hashed_identifiers"]
    }
  }
```

**Email and hashed identifiers (2 + 1 = 3 credits):**

```json
{
    "prospect_ids": "ee936e451b50c70e068e1b54e106cb89173198c4",
    "parameters": {
      "contact_types": ["email", "hashed_identifiers"]
    }
  }
```

**Backward Compatible (no parameters = email and phone):**

```
prospect_ids: ee936e451b50c70e068e1b54e106cb89173198c4
```
