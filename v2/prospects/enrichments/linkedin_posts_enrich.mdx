### Introduction

The **Individual's Social Media Presence Enrichments** API provides insights into a prospect's social media activity. This endpoint retrieves public posts from professional networks, allowing businesses to analyze engagement trends, content topics, and prospect interests for better outreach and marketing strategies.

<Warning>
  **Credit usage — charged per requested ID**

  Unlike other enrichment endpoints, which charge credits only for entity IDs that return results, this endpoint charges credits for **every `prospect_id` included in the request — whether or not results are returned**. A request that returns no posts still consumes credits.
</Warning>

<Icon icon="thumbtack" iconType="solid" color="red" /> **Key Benefits:**

- Gain **real-time visibility** into a prospect's social media activity.
- Understand **professional interests, opinions, and engagement**.
- Improve **personalized outreach** by leveraging recent posts and topics of discussion.
- Track changes in **professional communication patterns** over time.

<Note>
  **v2:** this endpoint accepts either a single ID (a string) or a list of up to 50 IDs — the separate `/bulk_enrich` route is gone. See [v2 conventions](/v2/conventions).
</Note>

## Enrich by prospect details instead of IDs

`prospect_ids` is the primary way to call this endpoint. If you don't have Explorium IDs yet, you can send `prospects_to_match` instead: up to 50 people, described with the same fields the [Match prospects](/v2/prospects/match_prospects) endpoint accepts (`full_name`, `company_name`, `email`, `phone_number`, `linkedin`, `business_id`). Each person is matched and enriched in the same call. Send **either** `prospect_ids` **or** `prospects_to_match`, never both (that returns a `422`). Any `parameters` the endpoint takes work the same either way.

<CodeGroup>
```json Request body
{
  "prospects_to_match": [
    { "full_name": "Jane Doe", "company_name": "Acme Corp" },
    { "full_name": "John Smith", "company_name": "Unknown Co" }
  ]
}
```

```json Response (data shortened)
{
  "response_context": {
    "correlation_id": "9a1c0e7f4b2d4c6e8f0a1b2c3d4e5f60",
    "request_status": "success",
    "time_taken_in_seconds": 1.42
  },
  "data": [
    {
      "input": { "business_id": null, "full_name": "Jane Doe", "company_name": "Acme Corp", "email": null, "phone_number": null, "linkedin": null },
      "prospect_id": "4f1d9c2e7a3b5c8d0e6f1a2b3c4d5e6f7a8b9c0d",
      "data": { "...": "same fields as an ID-based request" },
      "warnings": []
    },
    {
      "input": { "business_id": null, "full_name": "John Smith", "company_name": "Unknown Co", "email": null, "phone_number": null, "linkedin": null },
      "prospect_id": null,
      "data": null,
      "warnings": []
    }
  ],
  "total_results": 1,
  "total_matches": 1
}
```
</CodeGroup>

Each row echoes its `input` and returns the matched `prospect_id`. People who don't match come back with `prospect_id: null` and `data: null`, and aren't charged. `total_matches` counts the matched rows.

  <Accordion title="Credit Usage">
    This endpoint uses a different charging model than other enrichment endpoints:

    | Endpoint type | Charging model |
    | :-- | :-- |
    | Other enrichment endpoints | Credits charged **per entity ID that returns results** — no results, no charge. |
    | **This endpoint (LinkedIn posts)** | Credits charged **per requested `prospect_id`**, regardless of whether results are returned. |

    To avoid spending credits on IDs that are unlikely to return data, make sure you use **valid prospect IDs** retrieved from the **Match Prospects** endpoint.
  </Accordion>

<Icon icon="thumbtack" iconType="solid" color="red" /> **Key Consideration:**

- **Credits are charged per requested `prospect_id`, even when no results are returned** — unlike other enrichment endpoints, which charge only for IDs that return data.
- Posts retrieved are from publicly available social media content.
- Engagement data (likes, comments) may not always be available.
- Ensure **valid prospect IDs** (from **Match Prospects**) to retrieve accurate data.
- Use insights for **trend analysis, competitor research, and engagement tracking**.
